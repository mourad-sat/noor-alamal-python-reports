# منصة نور الأمل لتقارير برنامج الفرصة الثانية

تطبيق ويب باللغة العربية (RTL) مخصص لجمعية نور الأمل / برنامج الفرصة الثانية – الجيل الجديد، مبني بـ **Python + FastAPI + SQLAlchemy** ويصلح للنشر على Vercel بعد إعداد قاعدة بيانات PostgreSQL.

## وظائف النسخة الأولية

- لوحة قيادة تعرض عدد تقارير التكوين المهني والتأهيل التربوي والأنشطة الموازية، وسجلات الغياب، ونسبة الحضور وفق الأرقام المصرح بها في التقارير.
- إنشاء وعرض وتعديل وحذف تقارير الحصص والأنشطة، مع الأهداف وسير الحصة والنتائج والصعوبات والتوصيات وأعداد الحضور.
- تسجيل غياب المستفيدين بالاسم والتاريخ والفوج والسبب وحالة التبرير.
- كشف غياب قابل للطباعة مع تصفية الفترة والمجموعة.
- طباعة التقارير بصيغة رسمية مع توقيع المؤطر وختم الإدارة، واختيار **حفظ بصيغة PDF** من نافذة طباعة المتصفح.
- تصدير التقارير والغياب إلى CSV يدعم اللغة العربية (UTF-8 BOM) للاستخدام في Excel.
- دخول إداري محمي بكلمة مرور مشفرة PBKDF2 وجلسة محددة المدة ورموز CSRF.

> لا تتضمن هذه النسخة حسابات متعددة أو رفع الصور أو استيراد جماعي من Excel أو توليد PDF على الخادم؛ يمكن إضافتها في مرحلة لاحقة. اسم الجمعية والبرنامج مثبتان حاليًا في الواجهة والتقارير.

## 1. التشغيل على الحاسوب

يلزم Python 3.12 أو أحدث. شغّل هذه الأوامر داخل مجلد المشروع:

```bash
python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows:
# .venv\Scripts\activate
pip install -r requirements.txt
python scripts/make_secrets.py
```

بعد تشغيل السكربت، انسخ `.env.example` إلى `.env`، ثم **استبدل** سطري `APP_SECRET` و`ADMIN_PASSWORD_HASH` بالقيم التي أظهرها السكربت. احتفظ بكلمة مرور المدير في مكان آمن، ولا ترفع ملف `.env` إلى GitHub. يمكن ترك `DATABASE_URL` غير محدد محليًا لاستخدام SQLite تلقائيًا.

```bash
uvicorn app:app --reload
```

افتح http://127.0.0.1:8000 ثم سجّل الدخول باسم المستخدم `admin` وكلمة المرور التي اخترتها. سيُنشأ ملف قاعدة بيانات محلية تلقائيًا، وهو مستبعد من Git.

## 2. نشر الكود على GitHub

1. أنشئ مستودع GitHub جديدًا، مثل `noor-alamal-reports`، واختر **Private** إذا كان الفريق سيطور التطبيق داخليًا.
2. ارفع محتويات مجلد المشروع، **دون** ملف `.env` أو أي قاعدة بيانات محلية أو بيانات حقيقية للمستفيدين.
3. تحقق أن `.gitignore` يعمل وأن المستودع لا يحتوي كلمات مرور أو روابط قواعد بيانات تتضمن بيانات اعتماد.

أمثلة الأوامر بعد إنشاء المستودع:

```bash
git init
git add .
git commit -m "Initial Noor Al Amal reporting app"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/noor-alamal-reports.git
git push -u origin main
```

## 3. إنشاء قاعدة بيانات PostgreSQL مجانية (Supabase)

1. أنشئ حسابًا في https://supabase.com واختر مشروعًا من خطة Free **إذا كانت حدود وشروط الخطة ملائمة لك**.
2. افتح لوحة المشروع > **Connect** ثم انسخ رابط PostgreSQL ضمن **Session Pooler** (المنفذ `5432`) أو **Transaction Pooler** (المنفذ `6543`) وفق الإرشادات الحالية في لوحة المشروع. راجع متطلبات دعم IPv4/IPv6.
3. تأكد من أن الرابط يشمل اسم المستخدم وكلمة المرور واسم القاعدة، واستعمل ترميز URL لكلمة المرور عند وجود رموز خاصة مثل `@`, `#`, `/`.
4. استخدم هذا الرابط في متغير البيئة **`DATABASE_URL`** في Vercel، وليس داخل الكود.
5. سيُنشئ التطبيق تلقائيًا مخطط PostgreSQL باسم `noor_app` وجداول البيانات عند أول اتصال ناجح. هذا المخطط منفصل عن `public` المكشوف عادة عبر Supabase Data API. **لا تضفه** إلى مخططات Data API المكشوفة.

**مهم:** لا تحتفظ بتقارير أو بيانات غياب خاصة بالأطفال والمستفيدين في مستودع GitHub أو صفحة عامة. وفّر الوصول للموظفين المخولين فقط، واحترم متطلبات الموافقات وحماية المعطيات الشخصية المعمول بها. لا توجد نسخ احتياطية تلقائية ضمن التطبيق؛ نفّذ تصديرًا دوريًا محميًا أو استخدم خدمة نسخ احتياطي مناسبة.

## 4. نشر التطبيق على Vercel

1. سجّل الدخول إلى https://vercel.com، ثم **Add New > Project**، واختر مستودع GitHub.
2. استورد المستودع. Vercel يكتشف FastAPI تلقائيًا من `app.py` و`requirements.txt`، **ولا يحتاج Build Command مخصصًا أو ملف vercel.json**.
3. في **Settings > Environment Variables** أضف القيم التالية للبيئة Production:

| المتغير | القيمة |
|---|---|
| `ADMIN_USERNAME` | `admin` أو اسم تختاره |
| `APP_SECRET` | القيمة الطويلة الناتجة عن السكربت |
| `ADMIN_PASSWORD_HASH` | القيمة الناتجة عن السكربت بالكامل |
| `DATABASE_URL` | رابط الاتصال بقاعدة PostgreSQL الدائمة |

4. نفّذ **Deploy**. افتح نطاق التطبيق بامتداد `vercel.app`، وجرّب تسجيل الدخول وإنشاء تقرير ثم تحديث الصفحة.
5. أي تعديل على فرع GitHub المرتبط بالنشر سيؤدي عادة إلى نشر إصدار جديد تلقائيًا.

**لا تعتمد على SQLite أثناء العمل على Vercel**: نظام الملفات في الوظائف ليس مخزنًا دائمًا. التطبيق يمنع العمل في Vercel عند غياب `DATABASE_URL` ويعرض صفحة إعداد بدل تخزين تقارير حقيقية مؤقتًا.

### الكلفة والحدود

- GitHub: يمكن استضافة الكود ضمن خطته المجانية.
- Supabase Free: هناك حدود للسعة والنشاط؛ قد تتوقف المشاريع المجانية مؤقتًا عند غياب النشاط. تحقق من الشروط الحالية.
- Vercel Hobby: مجاني لكنه **مخصص للاستعمال الشخصي غير التجاري**. استخدام الجمعية أو الاستخدام المؤسسي قد يتطلب خطة مناسبة أو خدمة استضافة أخرى؛ تأكد من سياسة Vercel قبل النشر الفعلي.
- نطاق `.vercel.app` لا يتطلب شراء اسم نطاق مستقل.

### ملاحظات أمنية

- نسخة أولية بحساب مدير واحد؛ لا تشارك الحساب بين أعضاء الفريق إن أمكن. أضف نظام حسابات وصلاحيات قبل استخدام واسع النطاق.
- كلمات المرور لا تُحفظ بنص صريح في الكود، لكن حماية الحساب تعتمد على قوة كلمة المرور والاحتفاظ بسرية متغيرات البيئة.
- جلسات الدخول HttpOnly، وتستخدم HTTPS-only في Vercel، وجميع عمليات الكتابة تحتاج CSRF.
- يجب تقييد من يصل للتطبيق، وضمان نسخ احتياطي، ووضع سياسة احتفاظ ببيانات المستفيدين، خصوصًا إذا كانت بيانات قاصرين.

## حالة الربط الحالية (نوفمبر 2026)

- رابط التطبيق: https://noor-alamal-python-reports.vercel.app
- قاعدة البيانات الجديدة: Supabase project `mjpeudultagipkiqgyql` (`noor-alamal-python-reports-db`)، منطقة `eu-west-3`.
- الجداول: `noor_app.reports` و`noor_app.absences`، داخل مخطط خاص غير مكشوف للـ Data API.
- متغيرات Vercel المضبوطة: `APP_SECRET` و`ADMIN_USERNAME` و`ADMIN_PASSWORD_HASH` في Production.
- **يلزم ضبط `DATABASE_URL` قبل دخول التطبيق وحفظ التقارير.** لا تُدرج أي كلمة مرور في GitHub.

لإكمال `DATABASE_URL`: في لوحة Supabase للمشروع الجديد اضغط **Connect**، واختر **Transaction pooler**؛ انسخ عنوان PostgreSQL الكامل بعد استبدال `[YOUR-PASSWORD]` بكلمة مرور قاعدة البيانات، ثم أضفه بوصفه متغيرًا **Encrypted** في إعدادات Vercel لمشروع `noor-alamal-python-reports`، ضمن بيئة **Production**. إذا نسيت كلمة المرور، غيّرها من إعدادات قاعدة البيانات داخل Supabase. يجب نسخ اسم المضيف والمنفذ واسم المستخدم من لوحة Supabase نفسها، لا تخمينها من المنطقة.

بعد حفظ المتغير، نفّذ **Redeploy** لآخر إصدار Production ثم افتح `/health`. تظهر `status: ready` فقط إذا كانت بيانات الدخول المطلوبة مضبوطة وكان اتصال PostgreSQL ناجحًا. وفي حالة فشل الاتصال، يظهر `database-unavailable` مع HTTP 503، من دون كشف تفاصيل الاتصال.

عند إدخال بيانات المستفيدين الحقيقيين، طبّق أيضًا نظام صلاحيات حسب الموظف/المركز والنسخ الاحتياطي وسياسة الاحتفاظ بالبيانات؛ النسخة الحالية مناسبة للتهيئة والاختبار قبل الاستخدام الرسمي.
